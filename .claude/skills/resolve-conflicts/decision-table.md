# Conflict decision table

Legend: **AUTO** = resolve unattended · **AUTO + VERIFY** = resolve, then only accept it if the
named command passes · **ASK** = stop, escalate to a human (see `SKILL.md`'s "When this skill is
running unattended").

All commands assume the rebase convention from `SKILL.md`: `--ours` is the upstream tip
(`origin/main`), `--theirs` is your own commit.

| # | File class | Rule | Commands | Autonomy |
| --- | --- | --- | --- | --- |
| 1 | `docs/architecture/inventory.md` | Never merge the content — it's a pure function of the tree. Resolve **last**, after every source conflict is settled, so regeneration reflects the final tree. | `git checkout --ours docs/architecture/inventory.md && npm run docs:arch && git add docs/architecture/inventory.md` | **AUTO** |
| 2 | `docs/plan/ROADMAP.md` | Same reasoning as #1 — generated from unit frontmatter + `git log`, resolve last. | `git checkout --ours docs/plan/ROADMAP.md && npm run docs:plan && git add docs/plan/ROADMAP.md` | **AUTO** |
| 3 | `src/routes/modules/*.routes.tsx` | Both sides added route objects to the same array — union, append-only, **theirs first** (already on `origin/main`), yours appended after. Never reorder existing entries: `registry.ts` documents that react-router ranks by path specificity, so array order is semantically irrelevant, and reordering only widens the diff for the next conflict. A duplicate `path` value across the two sides is a genuine collision, not a mechanical conflict. | Hand-merge to `[...theirs, ...yours]`, `git add <file>`, then `rg 'path: "' src/routes/modules \| sort \| uniq -d` must be empty | **AUTO + VERIFY** (`npm run typecheck && npm run build`); duplicate path → **ASK** |
| 4 | `src/types/index.ts`, `src/lib/constants/index.ts` (compat barrels) | Both files are a header comment plus a flat list of `export *` re-exports. Union of both sides' lines, dedupe exact duplicates, **do not alphabetise or regroup** (`CLAUDE.md`: "Append, don't reorder" — reordering turns a small conflict into a whole-file conflict for everyone else in flight). Append yours below theirs. | Hand-merge, `git add <file>` | **AUTO + VERIFY** (`npm run typecheck`) |
| 5 | `src/types/<domain>.ts` | Union **if** the two sides added disjoint type names. If both sides define the *same* type name with different fields, that's two people modelling the same entity differently — a design disagreement, not something a rebase can settle. | `git log -1 --format=%B $(git rev-parse HEAD)` to read the other side's intent first; disjoint names → keep both blocks, theirs first, `git add <file>` | **AUTO + VERIFY** if disjoint (`npm run typecheck`); same name, different shape → **ASK** |
| 6 | `src/lib/constants/<domain>.ts` | Identical reasoning to #5. | Same as #5 | Same as #5 |
| 7 | `package-lock.json` | Never hand-merge, never resolve by picking a side wholesale. Resolve `package.json` first if it also conflicts (same version on both sides → trivial union; **different** versions of the same dependency → a compatibility decision, not mechanical). Then regenerate the lockfile from the resolved manifest. | Resolve `package.json` conflicts (if any) → `rm -f package-lock.json && npm install --package-lock-only && git add package-lock.json package.json` | **AUTO + VERIFY** (`npm ci && npm run build`); differing dependency versions in `package.json` → **ASK** |
| 8 | `docs/DECISIONS.md` | Append-only by its own stated contract, newest at the bottom. Union: theirs, then yours — never drop a line from either side. | Hand-merge to `theirs ++ yours`, `git add docs/DECISIONS.md` | **AUTO** |
| 9 | `docs/wip/*.md` | One file per branch by design (`docs/wip/README.md`) — a genuine *content* conflict on one claim file is structurally impossible. What looks like a conflict here is almost always a delete/modify: the other branch merged and deleted its own claim file as its final commit. Honour their delete; keep your own file untouched. | `git rm docs/wip/<their-branch>.md` for their deleted file; `git checkout --theirs docs/wip/<your-branch>.md && git add` for your own | **AUTO** |
| 10 | `src/index.css` (design tokens) | **Never auto-resolve.** Owner-gated per `docs/OWNERS.md`/CODEOWNERS. A conflict here means two people changed the design system in the same window; taking either side silently restyles every page in the app for everyone, and `.claude/rules/index-css-rules.md`'s token-promotion procedure has to be followed deliberately, not merged mechanically. | Report both hunks verbatim, plus `git log -1 --format=%B HEAD` for the other side's stated intent | **ASK — always** |
| 11 | `platform/src/components/ui/**` | **Never auto-resolve.** Owner-gated. If the other side's diff looks like a fresh `npx shadcn add --overwrite` regeneration, taking it wholesale wipes this repo's customizations (`isLoading`, radius, `bg-input-background`, `control-disabled*` — see `docs/architecture/ui.md`). If *your own* leaf-unit branch is touching a shared primitive at all, that's a lane violation, not just a hard conflict — the unit's spec was wrong to begin with. | Report both sides; name which customizations from `docs/architecture/ui.md` are at risk | **ASK — always** |
| 12 | `CLAUDE.md`, `.claude/**` | **Never auto-resolve.** Policy-as-code with no test suite, affecting every other developer's next session. A conflict here is also evidence the change shouldn't have ridden inside a unit/feature branch at all — `CONTRIBUTING.md` says policy changes get their own `policy/` branch. | Report both sides; recommend extracting the change to its own `policy/` branch | **ASK — always** |
| 13 | `src/pages/**`, `src/components/<Feature>/**`, `src/hooks/<domain>/**`, `src/services/<domain>.ts` (unit-owned files) | Should be **impossible** under correct lane partitioning (`docs/plan/README.md`, `.claude/skills/build-app/SKILL.md`) — two in-flight units are never supposed to share these paths. A conflict here is evidence the lane model broke down, not just that a merge is hard, and resolving it mechanically would hide that. | Report the conflict **and** flag it as a likely lane-partitioning failure — don't just resolve and move on | **ASK — always** |
| 14 | Anything not listed above | Not classified here → not safe to guess about. | — | **ASK** |
